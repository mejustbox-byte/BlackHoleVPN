# Экспорт клиентского JSON и FinalMask

`python3 -m blackhole.export` создаёт самостоятельный клиентский JSON Xray из существующей серверной конфигурации и выбранного устройства. Экспорт не меняет сервер, не создаёт UUID и не запускает клиент. Поддерживаются XHTTP + REALITY (`stream-one`) и TCP + REALITY + Vision; фрагментация FinalMask `tlshello` включается только явно.

## Подготовка приватных файлов

Серверная конфигурация и файл с одним значением REALITY public key/password должны быть обычными файлами владельца процесса с правами `0600` (без symlink). Каталог вывода должен принадлежать тому же пользователю и иметь права `0700`. Запускайте экспорт в доверенной среде оператора. Приватный ключ сервера не передаётся клиенту.

Публичная часть должна соответствовать приватному ключу действующего сервера. Экспортёр не проверяет соответствие ключевой пары: оно устанавливается при выпуске и подтверждается сетевым подключением. В примере все пути и имена условные; секретные значения в аргументы команд не подставляются.

```sh
install -d -m 700 /private/client-configs
python3 -m blackhole.export \
  --config /private/server.json --name test-device \
  --address server.example.org --public-key-file /private/reality-public \
  --transport xhttp --listen-port 10808 \
  --output /private/client-configs/xhttp.json --xray /path/to/xray
```

Xray должен быть проверенной версией, совместимой с сервером и используемыми параметрами. Перед публикацией файла экспортёр вызывает `xray run -test` на временном файле с расширением `.json`. Сообщения Xray подавляются, чтобы не раскрывать конфигурацию. При ошибке файл назначения не создаётся. Успешная проверка синтаксиса не доказывает сетевое подключение.

Результат записывается с правами `0600`. Уже существующий файл, каталог или symlink не заменяется: выберите новое имя. Временный файл удаляется при штатном завершении или обработанном исключении. После аварийного завершения процесса проверьте приватный каталог на оставшиеся `.client-*.json`; они защищаются как профили. Ничего не выводится в stdout, кроме сообщения об успехе; ошибки CLI не содержат исходных данных.

## Четыре варианта

Для каждого вызова повторите аргументы `--config`, `--name`, `--address`, `--public-key-file` и `--xray` из примера выше.

| Вариант | Аргументы | Отдельный файл |
| --- | --- | --- |
| XHTTP без фрагментации | `--transport xhttp` | `xhttp.json` |
| XHTTP с фрагментацией | `--transport xhttp --fragment` | `xhttp-fragment.json` |
| TCP/Vision без фрагментации | `--transport tcp` | `vision.json` |
| TCP/Vision с фрагментацией | `--transport tcp --fragment` | `vision-fragment.json` |

По умолчанию `--fragment` добавляет клиентский `streamSettings.finalmask.tcp`: `type=fragment`, `packets=tlshello`, `lengths=["10-20"]`, `delays=["10-20"]`, `maxSplit="3-6"`. Длины — байты, задержки — миллисекунды. Допускается настройка, например:

```sh
# Добавляется к полному вызову экспортёра:
# --fragment --fragment-length 10-20 --fragment-length 20-40 \
# --fragment-delay 5-10 --fragment-max-split 3-6
```

Параметры фрагментации без `--fragment` отклоняются. Их диапазоны ограничены экспериментальными границами из `blackhole.finalmask`; это не автоматически подобранные значения. Для сравнения меняйте один параметр за раз.

Python API: `blackhole.export.make_client_config(config, name, address, public_key, transport='xhttp', fragment=False, listen_port=10808)` (последние параметры передаются по имени). API возвращает словарь, а не пишет файл; проверка Xray и приватная запись выполняются CLI или `write_validated`.

## Запуск и ограничения клиента

```sh
/path/to/xray run -config /private/client-configs/xhttp-fragment.json
curl --fail --show-error --connect-timeout 10 --max-time 30 \
  --proxy socks5h://127.0.0.1:10808 --noproxy '' https://example.com/
```

JSON содержит единственный SOCKS-вход на `127.0.0.1`, UDP выключен; аутентификации локального SOCKS нет. Единственный outbound — VLESS, прямого резервного outbound нет. Два процесса на одном локальном порту одновременно не запускаются: останавливайте предыдущий либо задавайте разные `--listen-port`.

Это конфигурация ядра с локальным SOCKS, не готовый TUN/VPN-профиль iOS и не системный kill switch. Приложения вне SOCKS могут выходить напрямую; DNS/IPv6 и маршрутизация GUI требуют отдельной проверки. При импорте полного JSON в Happ приложение может иначе обрабатывать собственные настройки маршрутизации — сверяйтесь с [документацией разработчика](https://www.happ.su/main/dev-docs/examples-of-links-and-parameters) и проверяйте поведение конкретной версии.

Обычные VLESS URI и QR-коды генератора по-прежнему не содержат FinalMask. Совместимость JSON в GUI Windows/iOS не подтверждается успешным запуском Linux Xray.

## Проверенные результаты

[Результаты испытаний](validation-results.md) включают четыре варианта на Xray 26.10.21. Фрагментация ClientHello не гарантирует отдельный TCP-пакет на каждый фрагмент, устойчивость к DPI или выигрыш производительности. Для оценки сетевого эффекта нужны повторяемые A/B-испытания в целевых сетях и анализ захвата трафика на собственном стенде. [Документация FinalMask](https://xtls.github.io/en/config/transports/finalmask.html#fragment).
