# Импорт JSON в v2rayN и Happ

Для каждого устройства выпускаются четыре отдельных JSON из [экспортёра](client-json-export.md). UUID устройства общий для четырёх вариантов, у разных устройств UUID различаются. Секретные профили передаются приватно и не входят в репозиторий.

| Файл | Транспорт | FinalMask |
| --- | --- | --- |
| `xhttp-plain.json` | XHTTP + REALITY, stream-one | выключен |
| `xhttp-finalmask.json` | XHTTP + REALITY, stream-one | fragment/tlshello |
| `tcp-vision-plain.json` | TCP + REALITY + Vision | выключен |
| `tcp-vision-finalmask.json` | TCP + REALITY + Vision | fragment/tlshello |

В вариантах с FinalMask: `lengths=["10-20"]`, `delays=["10-20"]` миллисекунд, `maxSplit="3-6"`; fingerprint всех четырёх — `firefox`. Не включайте дополнительно глобальную фрагментацию или другую маску при сравнении. Обычные VLESS-ссылки и ранее созданные QR-коды этих настроек не содержат.

## Перед импортом

- Получите только комплект своего устройства и проверьте срок действия стенда по приватной инструкции. Импорт JSON не продлевает доступ и не обновляется как подписка.
- Используйте Xray-ядро, поддерживающее эту схему FinalMask. Сетевая проверка выполнялась на 26.10.21; конкретные сборки GUI и другие версии ядра ещё требуют проверки. Не заменяйте ядро на sing-box в этих JSON.
- Передавайте файлы доверенным защищённым каналом, не через публичные хранилища и JSON/QR-конвертеры. Архив ZIP содержит секреты и не зашифрован. Храните распакованные файлы в приватной папке; на Windows ограничьте NTFS-доступ своим пользователем.
- Одновременно запускается один профиль. Четыре файла используют один и тот же локальный порт в пределах комплекта. Закройте предыдущий профиль перед переключением.

## Windows: v2rayN

1. Установите v2rayN из [официальных релизов](https://github.com/2dust/v2rayN/releases). Запишите версии v2rayN и Xray. Распакуйте приватный комплект Windows в папку вне каталогов Git и облачной синхронизации.
2. Откройте меню серверов и **Add custom configuration server / Добавить сервер с пользовательской конфигурацией**. Это полный JSON, не обычная форма добавления VLESS. Через выбор файла укажите `xhttp-plain.json`, задайте понятное название и выберите ядро **Xray**. Названия пунктов зависят от языка и версии приложения.
3. Для первой проверки оставьте поле SOCKS-port пользовательского профиля незаданным/нулевым, если версия позволяет это. Тогда используйте прямой локальный SOCKS из файла, а не системный прокси, TUN или дополнительную маршрутизацию v2rayN. Например, в подготовленном комплекте Windows локальный порт — **10818**; в самостоятельно экспортированном JSON читайте `inbounds[0].port`.
4. Сохраните и активируйте профиль. Выполните проверку PowerShell, подставив фактический локальный порт. Вызов `curl.exe` важен: `curl` в некоторых версиях PowerShell является псевдонимом другой команды.

```powershell
$ProxyPort = 10818
curl.exe --fail --show-error --connect-timeout 10 --max-time 30 --proxy "socks5h://127.0.0.1:$ProxyPort" --noproxy "" https://example.com/
```

5. Остановите профиль. Добавьте остальные три JSON тем же способом и проверяйте по одному. После выключения ядра повтор команды должен завершаться ошибкой. Не повторяйте неуспешный запрос напрямую.
6. Если нужен фронтальный сервис v2rayN для системного прокси/маршрутизации, укажите в поле SOCKS-port пользовательского профиля **10818**, то есть порт JSON. По [официальному описанию UI](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui) это запускает дополнительный фронтальный сервис. Его собственный локальный порт должен отличаться от 10818. Такой режим проверяйте отдельно: фронтальный сервис может применять собственные маршруты.
7. Если оставить поле SOCKS-port пустым, v2rayN может не знать порт пользовательского JSON: включение системного прокси само по себе не гарантирует работу. Для первоначального теста используйте явный curl через порт файла.

Ошибки bind означают конфликт локального порта; остановите предыдущий экземпляр. Ошибка неизвестного поля `finalmask`/`password` или вида маски требует проверки версии ядра. Не удаляйте FinalMask из экспериментального файла ради успешного импорта: это изменит проверяемый вариант. Подробности выбора файла и ядра также доступны в [исходном коде v2rayN](https://github.com/2dust/v2rayN/blob/master/v2rayN/ServiceLib/ViewModels/AddServer2ViewModel.cs).

## iOS: Happ

1. Установите Happ по ссылке разработчика из [официального репозитория](https://github.com/HappDev/happ_su); запишите версии приложения, iOS и встроенного Xray. Передайте комплект iOS на устройство выбранным вами защищённым способом. ZIP сначала распакуйте в приложении «Файлы»; в Happ выбирайте JSON, а не ZIP.
2. Добавьте **полную JSON-конфигурацию** через доступный в вашей версии пункт импорта файла/JSON. Если версия принимает JSON через буфер, скопируйте целиком содержимое одного файла и используйте импорт из буфера. Начните с `xhttp-plain.json` и дайте записи отличимое имя. Не заменяйте файл VLESS-ссылкой: она не сохраняет FinalMask.
3. По [документации Happ](https://www.happ.su/main/dev-docs/examples-of-links-and-parameters), полный JSON передаётся Xray как есть, а обычные настройки маршрутизации приложения не применяются к нему стандартным способом. Документация подтверждает поддержку JSON, но не единый путь меню для всех iOS-сборок. Если в вашей версии отсутствует импорт полного JSON или файл не распознаётся, отметьте **импорт не подтверждён/не поддерживается этой версией**; не считайте обычный URI эквивалентной проверкой FinalMask.
4. Убедитесь, что приложение сохранило `outbounds[0].streamSettings.finalmask` в варианте `*-finalmask.json` и что поля нет в `*-plain.json`. Если редактор показывает только обычные поля VLESS, это ещё не доказывает сохранение полного JSON. Не публикуйте конфигурацию или скриншот секретных полей.
5. В комплекте iOS вход — SOCKS на **127.0.0.1:10808**, без аутентификации и UDP. Это ядро прокси, не самостоятельный iOS Packet Tunnel. Happ должен связать собственный VPN-туннель с этим входом. Если приложение требует другой порт, настройте его привязку к 10808 либо согласованно измените порт и повторно проверьте JSON. При наличии режима аутентификации SOCKS выбирайте `from-json` для этого теста; не включайте доступ из локальной сети. [Описание режимов Happ](https://github.com/HappDev/happ_su/blob/main/dev-docs/app-management.md).
6. Подключите выбранный профиль, разрешив создание VPN-конфигурации iOS. Проверьте HTTPS в Safari. Успешный старт ядра и значок VPN не доказывают, что Safari направлен в SOCKS: сверьте выходной адрес приватно через доверенную конечную точку или выполните тест при остановке сервера. Влияние настроек DNS Happ проверяется отдельно.
7. Повторите для остальных трёх файлов, по одному, на Wi-Fi и мобильной сети. Если JSON импортируется, но VPN-туннель не связан с его SOCKS-входом, результат отмечайте как неработающую интеграцию приложения; Linux-проверка ядра этого не исключает.

Поддержка JSON в Happ описана разработчиком; импорт именно этих файлов и привязка туннеля на физическом iPhone ещё не проверены. Не включайте неподтверждённые настройки TUN/DNS в общий шаблон как заведомо рабочие.

## Сравнение и отчёт

Сначала сравнивайте `plain` и `finalmask` одного транспорта, затем второй транспорт. Не меняйте одновременно сеть, fingerprint, версию ядра и параметры маски. Для каждого испытания фиксируйте версию приложения/ядра, сеть, импорт, старт, HTTPS, время подключения и ошибки. Проверки с остановкой сервера и отзывом UUID проводятся отдельно с оператором; они не должны останавливать другие службы VPS.

| Устройство/сеть/версии | Файл | Импорт | HTTPS | Сбой без прямого выхода | DNS/IPv6 |
| --- | --- | --- | --- | --- | --- |
| заполняется приватно | xhttp-plain.json | not_run | not_run | not_run | not_run |
| заполняется приватно | xhttp-finalmask.json | not_run | not_run | not_run | not_run |
| заполняется приватно | tcp-vision-plain.json | not_run | not_run | not_run | not_run |
| заполняется приватно | tcp-vision-finalmask.json | not_run | not_run | not_run | not_run |

Отсутствие прямого outbound внутри JSON не предотвращает прямой трафик приложений вне этого SOCKS. Настройки GUI, TUN, DNS/IPv6 и kill switch требуют самостоятельной приёмки. Эти проверки не доказывают эффективность против DPI.
