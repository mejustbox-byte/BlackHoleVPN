# Экспериментальная конфигурация сервера

См. [актуальные результаты испытаний](validation-results.md) и [проверку Windows/iOS](windows-ios-testing.md). Передача данных настоящим Xray с внешнего Linux-клиента подтверждена; готовый production-установщик и работа GUI-клиентов пока не подтверждены.

Это предварительная версия, не production-релиз. На Debian 13 проверены отдельные тестовые экземпляры Xray и подключение Linux-клиента; production-служба, изменения firewall и восстановление после перезагрузки не проверены. Инструмент не устанавливает Xray, не перезапускает сервис и не выдаёт профили через CLI; экспериментальный Python-генератор описан в [двух транспортах](dual-transport.md). Проводите испытания на отдельной машине с доступом к консоли.

## Подготовка

Установите Python 3 и самостоятельно установите проверенный Xray-core из официального источника, зафиксировав версию и проверив происхождение файлов. Следуйте [официальной документации Xray](https://xtls.github.io/en/document/command.html). Определите подходящий REALITY target, проверив его сертификат, доступность и риск злоупотребления fallback. Не указывайте target, не понимая эти ограничения. Обеспечьте синхронизацию времени, ограничьте SSH и заранее сохраните доступ к консоли.

Сгенерируйте ключи командой `xray x25519`. Сохраните **приватный ключ** в отдельный файл, доступный только администратору. Публичную часть также храните как чувствительные данные; она потребуется клиентам. Формат файлов и вывод xray могут различаться между версиями: в файл приватного ключа поместите только само значение. Не вставляйте ключи в командную строку, Git, журналы или issue.

Создайте приватную директорию и конфигурацию, заменив hostname на выбранный target:

```sh
sudo install -d -m 700 /etc/blackholevpn
sudo python3 -m blackhole.cli --config /etc/blackholevpn/config.json init --target example.org --private-key-file /путь/к/файлу-приватного-ключа
sudo python3 -m blackhole.cli --config /etc/blackholevpn/config.json add-client phone
sudo python3 -m blackhole.cli --config /etc/blackholevpn/config.json list-clients
sudo python3 -m blackhole.cli --config /etc/blackholevpn/config.json validate
```

Запускайте команды из корня репозитория. Если Xray не находится через PATH, укажите `--xray /полный/путь/к/xray` перед подкомандой. При добавлении клиента в конфигурации создаётся UUID, который хранится в конфиденциальном файле. Секретные данные для настройки совместимого клиента — адрес сервера, порт, UUID, REALITY serverName, shortId и соответствующая публичная часть ключа; для текущей конфигурации flow — `xtls-rprx-vision`. Выдавайте профиль через защищённый канал. Формат профиля зависит от версии клиента и здесь не проверен.

Для отзыва выполните `sudo python3 -m blackhole.cli --config /etc/blackholevpn/config.json revoke-client phone`. Изменения становятся действительными только после перезапуска вручную настроенной службы Xray. Перезапуск может завершить существующие соединения. До перезапуска сделайте защищённую резервную копию и убедитесь, что есть возможность откатить изменения. Удаление UUID не обязательно немедленно завершает уже установленные сессии.

## Ограничения безопасности

Файл должен находиться в приватном каталоге, куда не могут писать другие пользователи. При записи создаётся файл с правами 0600; владелец выполняющего пользователя должен иметь права на каталог. Операторский CLI сериализует полный цикл изменений через flock и автоматически сохраняет прежнюю конфигурацию перед заменой. Каталог должен быть приватным (`0700`), файлы и ключи — приватными (`0600`) и принадлежать выполняющему пользователю. [Резервные копии и восстановление](config-transactions.md). После изменений инструмент вызывает `xray run -test`; неуспешная проверка оставляет прежний файл. Это не доказывает доступность сети или безопасность конфигурации. Перед заменой сохраняйте резервную копию самостоятельно. Защищайте копии так же, как ключи.

Прямой выход сервера `freedom` позволяет авторизованным клиентам обращаться к ресурсам, доступным серверу, в том числе к внутренним адресам: сетевые ограничения и изоляция должны быть настроены отдельно. Не используйте конфигурацию на сервере с доступом к чувствительным внутренним сетям без дополнительных правил. REALITY fallback может быть использован посторонними для пересылки трафика. Логи ОС, Xray и хостинга следует отдельно изучить; утверждение об отсутствии журналов не подтверждено.
