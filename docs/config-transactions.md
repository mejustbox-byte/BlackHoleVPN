# Транзакции конфигурации, резервные копии и восстановление

Операторский CLI предназначен для Linux и локальной файловой системы. Все его операции над одним путём сериализованы межпроцессным `flock`: блокировка охватывает чтение, изменение, проверку и запись. Тайм-аут ожидания — 10 секунд. Это защита от конкурирующих экземпляров CLI на одном узле, не распределённая транзакция нескольких VPS.

## Приватные пути и совместимость

Каталог конфигурации должен принадлежать выполняющему пользователю и иметь права `0700`; конфигурация и файл ключа — обычные приватные файлы этого пользователя (`0600`, без группового/чужого доступа). Symlink для конфигурации, блокировки и каталога копий отклоняется; конфигурации с несколькими hardlink также отклоняются. Используйте доверенные родительские каталоги. Если конфигурация принадлежит сервисному пользователю, операторский процесс запускается от его имени. Возможность перезапуска службы предоставляется отдельно.

Усиление проверки прав может отклонить ранее допускавшиеся файлы. Исправляйте владельца/права адресно после проверки пути и назначения. Не применяйте рекурсивный `chmod` к существующим системным каталогам.

Пути относительно `server.json`:

- `.server.json.lock` — постоянный файл блокировки с правами `0600`; его нельзя удалять во время работы операторских процессов;
- `.server.json.backups/` — приватный каталог `0700`;
- `<revision>.json` внутри каталога копий — снимок `0600`, идентификатор из 32 шестнадцатеричных символов.

## Порядок записи

1. Взять блокировку и прочитать приватную конфигурацию.
2. Сформировать кандидат в том же каталоге, записать с `0600` и `fsync`.
3. Выполнить настоящий `xray run -test` с ограничением времени, не выводя его сообщения.
4. Перед заменой существующего файла сохранить его точные байты в новую резервную копию и синхронизировать копию/каталог.
5. Атомарно заменить основной файл и синхронизировать родительский каталог.

Если проверка кандидата или создание копии не прошли, прежний файл остаётся. При ошибке `os.replace` прежний файл также сохраняется. Если ошибка диска произошла после успешного rename, но до завершения fsync каталога, результат записи может быть неопределённым: остановите дальнейшие изменения и проверьте основной файл и копии. Не считайте любую ошибку гарантией отсутствия изменений.

Блокировка не мешает root или другим инструментам, которые её не используют, изменять файл. Прямое редактирование одновременно с CLI запрещено процедурой эксплуатации. После аварийного завершения проверьте оставшиеся `.blackhole-*.json`: они могут содержать секреты. Постоянную `.lock` не удаляйте; ОС освобождает flock при завершении процесса.

## Явная копия и восстановление

Команды из корня проекта, значения путей условные:

```sh
python3 -m blackhole.cli --config /private/server.json --xray /path/to/xray backup
python3 -m blackhole.cli --config /private/server.json list-backups
python3 -m blackhole.cli --config /private/server.json --xray /path/to/xray restore REVISION
```

`backup` сначала проверяет действующую конфигурацию Xray и выводит только идентификатор новой копии. `list-backups` выводит идентификаторы; их лексикографический порядок не является временем создания.

`restore` принимает только идентификатор, не произвольный путь. Выбранная копия проверяется на структуру управляемых inbound и настоящим Xray до записи. Текущий файл, если он есть, сохраняется отдельным снимком. Можно восстановить отсутствующий или повреждённый текущий файл из корректной копии. При ошибочной/несовместимой копии текущий файл не меняется.

Восстановление сверяется с независимым [реестром устройств и отзыва](device-registry.md): списки UUID строятся из актуальных active-записей, а не из snapshot. Для ранее созданных конфигураций требуется явная миграция `registry-init`. Сам реестр нельзя откатывать вместе с конфигурацией.

## Применение и пределы гарантии

CLI **не перезапускает Xray**. Проверка файла и его атомарная запись не означают успешное применение службой, сетевую доступность или немедленное прекращение старых сессий. Перезапускается только специально настроенный экземпляр, после проверки служебного имени, доступа к консоли и плана отката. Отдельный [операторский apply/health-check/rollback](health-checked-apply.md) применяется только по явной policy к выделенному экземпляру. Обычный CLI по-прежнему не перезапускает Xray. Согласованный отзыв UUID/подписки — следующий этап.

Копии содержат серверный приватный ключ и UUID. Они не зашифрованы, не очищаются автоматически и остаются на том же диске. Контролируйте размер, определите сроки хранения и организуйте отдельное шифрованное off-site-копирование с испытанием восстановления. Этот механизм сам по себе не защищает от потери VPS или компрометации root.

Существующие процессы/конфигурации на других путях не изменяются. В Python API `save_validated` блокирует публикацию; собственный read/modify/write-код должен удерживать `config_store.locked(path)` на всём цикле и использовать `publish` внутри него.
