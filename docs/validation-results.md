# Подтверждённые проверки прототипа

Дата: 29 октября 2026 года. Среда сервера: Debian 13.4, x86_64, Python 3.13.5, Xray-core 26.10.21. Исходная версия проекта: `09d9c05` с исправлением расширения временных конфигураций на `.json`. Приватные адреса, порты, UUID, ключи и профили в отчёт не включены.

## Результаты

| Проверка | Результат | Границы вывода |
| --- | --- | --- |
| `unittest discover -s tests -v` на VPS с `BLACKHOLE_TEST_XRAY` | 50/50, без пропусков | Включает настоящий Xray при init, добавлении, валидации, экспорте четырёх JSON и отзыве клиента |
| XHTTP + REALITY, `stream-one`, fingerprint `firefox` | pass | Настоящие процессы клиента/сервера, конфигурации из VLESS-профилей генератора |
| TCP + REALITY + Vision, fingerprint `firefox` | pass | Настоящие процессы клиента/сервера |
| HTTPS download/upload через каждый транспорт | pass | По 1 МиБ в каждом направлении; содержимое download и SHA256 upload проверены на контролируемом HTTPS-стенде |
| HTTPS к внешнему сайту через каждый транспорт | pass | Проверена TLS-валидация без отключения проверки сертификата |

| Остановка сервера при активном Linux SOCKS-клиенте | pass | Явный SOCKS-запрос завершается ошибкой, прямого повтора нет; это не тест системного kill switch |
| Отзыв UUID из обоих inbound с перезапуском тестового экземпляра | pass | Новые соединения отклонены и в loopback-, и во внешнем испытании |
| REALITY target: TLS-сертификат, TLS 1.3, ALPN h2 | pass | Сетевая доступность в момент проверки; это не полный аудит target или fallback |
| Сохранение существующих служб и настроек доступа | pass | Службы продолжали работать; после очистки набор слушающих портов и файлы SSH/firewall/fail2ban совпали с исходными |

Конфигурации тестового стенда отличались от базового генератора: временные порты, ограниченные маршруты к HTTPS-стенду и внешней проверочной странице, ограничения скорости REALITY fallback. Для HTTPS-стенда на loopback была разрешена только одна TCP-пара адрес/порт через `freedom.finalRules`; в Xray этой версии частные и зарезервированные адреса по умолчанию блокируются. Это исключение не требуется для обычного выхода к публичным сайтам. См. [официальную документацию Freedom](https://xtls.github.io/en/config/outbounds/freedom.html).

Для проверки URI применялось преобразование параметров ссылок в конфигурацию Xray. Импорт URI в GUI-приложения этим не подтверждён. Одноразовые процессы завершены и секреты удалены; отдельно подготовленный стенд для ручных клиентских испытаний имеет собственный ограниченный срок жизни.

## Что ещё не проверено

- Windows, iOS, их приложения и встроенные ядра: [инструкция и таблица результатов](windows-ios-testing.md).
- Вторая серверная площадка, повторные измерения в целевых Wi-Fi/мобильных сетях, устойчивость к DPI.
- DNS/IPv6/WebRTC, TUN/kill switch и отсутствие утечек при сбоях.
- Полный анализ злоупотребления REALITY fallback; ограничение скорости не устраняет все риски.
- HTTPS-подписка, связанный отзыв подписки/UUID, автоматическое переключение маршрутов.
- Перезагрузка, обновление с откатом и восстановление на реальной инфраструктуре.

Эти результаты подтверждают ограниченную работоспособность двух транспортов. Они не означают готовность публичного релиза, универсальный обход блокировок, анонимность или отсутствие журналов ОС/хостинга.

## Экспорт JSON и FinalMask: четыре варианта

Дополнительно проверен CLI `python3 -m blackhole.export`. Каждый JSON сформирован этим экспортёром на VPS, проверен командой `xray run -test`, затем передан по SSH внешнему Linux-клиенту. SSH использовался только для управления и передачи файлов; VLESS-трафик шёл напрямую к публичным тестовым портам VPS. На обеих сторонах Xray 26.10.21, fingerprint `firefox`.

| Экспортированный JSON | Проверка Xray | HTTPS download 1 МиБ | HTTPS upload 1 МиБ | Внешний HTTPS | Новое соединение после отзыва UUID |
| --- | --- | --- | --- | --- | --- |
| XHTTP, без FinalMask | pass | pass | pass | pass | отклонено |
| XHTTP, FinalMask tlshello | pass | pass | pass | pass | отклонено |
| TCP/Vision, без FinalMask | pass | pass | pass | pass | отклонено |
| TCP/Vision, FinalMask tlshello | pass | pass | pass | pass | отклонено |

Параметры fragment: `lengths=["10-20"]`, `delays=["10-20"]`, `maxSplit="3-6"`. Содержимое загрузки и SHA256 выгрузки проверены; TLS-сертификат HTTPS-стенда проверялся по его отдельному доверенному сертификату, без `--insecure`. После отзыва серверного UUID перезапускался только одноразовый тестовый экземпляр.

Тестовые процессы завершены, временные конфигурации и ключи удалены. Отдельный стенд для ранее выданных Windows/iOS-профилей продолжал работать; его профили не менялись. Производственные службы, SSH и firewall не менялись.

Это по одному сетевому испытанию каждого варианта в одной сети. Захват пакетов и A/B-оценка при DPI не проводились: успешная передача подтверждает совместимость JSON и ядра, а не эффективность маскировки или преимущество скорости. Windows/iOS GUI с этими JSON пока не проверены. [Команды экспорта и ограничения](client-json-export.md).

## Комплекты для ручного импорта Windows/iOS

Для двух отдельных UUID устройств подготовлено по четыре JSON из экспортёра: XHTTP и TCP/Vision, с FinalMask и без него. Все восемь файлов приняты Xray 26.10.21 на VPS и затем проверены настоящими HTTPS-запросами с внешнего Linux-клиента. Параметры сервера, UUID и срок действующего стенда не менялись; перезапуск сервера не требовался.

В комплекте Windows локальный SOCKS выбран на 10818 для отделения от обычного фронтального порта v2rayN; в iOS-комплекте — 10808. Приватные ZIP содержат JSON, инструкцию и SHA256-суммы; ZIP не зашифрован и передаётся только защищённым каналом. В публичный репозиторий файлы профилей и архивы не включаются.

Импорт конкретных файлов в v2rayN/Happ, встроенные ядра на физических Windows/iOS, привязка туннеля Happ и DNS/IPv6 остаются `not_run`. [Инструкция импорта и границы проверки](json-import-happ-v2rayn.md).

## Операторские транзакции конфигурации

В отдельном каталоге и transient systemd-процессе на Debian 13.4 проверены **58 тестов с настоящим Xray 26.10.21, без пропусков**. Включены шесть параллельных CLI-процессов без потери изменений, безопасный отказ валидации/копирования/rename, ограниченное ожидание lock, восстановление повреждённого или отсутствующего текущего файла и защита путей. Реальный Xray проверяет также backup/restore и четыре варианта экспорта.

Действующий клиентский тестовый стенд продолжал работать; его конфигурация и процесс не применялись заново. Испытание атомарной записи не проверяет применение службы, distributed revocation или off-site disaster recovery. Эти критерии вынесены в [план эксплуатации](production-roadmap.md).

## Реестр устройств: восстановление без возврата отозванного UUID

В отдельной staging-копии на Debian 13.4 с Xray 26.10.21 прошли **67 тестов, без пропусков**. Реальный Xray проверяет backup → отзыв → restore; списки разрешений берутся из независимого реестра. Дополнительные тесты проверяют повреждение/исчезновение authority, повторную выдачу имени, сбой записи, сохранность tombstone, обход через низкоуровневую публикацию и неуправляемый inbound.

Отдельно выполнена передача данных настоящими клиентами и сервером Xray на loopback VPS, с доступом к внешнему REALITY target и HTTPS-сайту. До отзыва оба тестовых устройства успешно передали по 1 МиБ в каждом направлении и выполнили внешний HTTPS-запрос через XHTTP и TCP/Vision. После отзыва первого устройства, применения к одноразовому серверу и восстановления старого snapshot:

| Устройство | XHTTP | TCP/Vision |
| --- | --- | --- |
| отозванное | новое HTTPS-соединение отклонено | новое HTTPS-соединение отклонено |
| второе активное | HTTPS-загрузка успешна | HTTPS-загрузка успешна |

Списки разрешений при restore перестроены из актуального реестра; тестовый экземпляр перезапускался для проверки новых соединений. CLI сам не применяет службу. Действующий клиентский стенд не мигрировался и не перезапускался: SHA256 его конфигурации и PID до/после испытания совпали. Временные процессы завершены, временные данные удалены.

Эта проверка подтверждает узловую защиту при сохранности актуального реестра. Она не подтверждает общий отзыв на нескольких VPS, блокировку подписки, немедленное завершение старых сессий или защиту от намеренного отката самого authority оператором/root. [Модель и миграция](device-registry.md).
