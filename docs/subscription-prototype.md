# Прототип выдачи подписок

Экспериментальный Python-модуль `blackhole.subscription` хранит предоставленные оператором VLESS-ссылки и выдаёт их в виде base64-списка через WSGI. Это внутренняя библиотека, не готовый сервис: CLI управления, HTTPS, ограничение запросов, журналирование без токенов, управление пользователями и интеграция с Xray отсутствуют. Не открывайте этот прототип в интернет и не используйте настоящие профили до реализации и проверки этих компонентов.

`connect(path)` создаёт SQLite-базу; `issue(db, profiles)` проверяет список из 1–10 VLESS URI и возвращает случайный токен; `update(db, token, profiles)` атомарно заменяет набор; `revoke(db, token)` отзывает только подписку. `application(path)` выдаёт ответ на GET `/s/<token>` с `Cache-Control: no-store`. Токен сохраняется в базе только в виде SHA-256, но сами профили хранятся в базе в обратимом виде. База, её журналы и резервные копии содержат секреты: используйте отдельный приватный каталог и защиту файлов и шифрование резервных копий. Токен невозможно восстановить из базы: сохраняйте его безопасно при выдаче.

Отзыв подписки **не блокирует существующие VLESS UUID** и не разрывает соединения: доступ необходимо отозвать отдельно в Xray и применить конфигурацию. Валидация URI ограничена базовой структурой и не доказывает, что профиль поддерживается клиентом, работает на сервере или безопасен. Прототип не формирует XHTTP-профиль, не включает автоматический выбор маршрута и не гарантирует совместимость формата. Изменение списка выполняется в одной транзакции; ошибки проверки оставляют прежний набор. Серверные приватные ключи не должны помещаться в профили.

Локальные проверки: `python3 -m unittest discover -s tests -v`. Для следующего этапа необходимы настоящий Xray, клиентские тесты, ограничение доступа и запросов, конфигурация HTTPS и независимая проверка отсутствия токена во всех логах reverse proxy и приложения.
