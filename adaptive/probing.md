# Диагностика маршрутов через локальные прокси

Экспериментальный одноразовый диагностический запуск выполняет HTTPS HEAD к контрольному ресурсу через отдельный локальный HTTP-прокси каждого маршрута. Используется HTTP CONNECT, обычная проверка TLS-сертификата и имени, без прямого сетевого fallback. Успех — только HTTP 204; перенаправления и прочие ответы считаются ошибками. Пробы не измеряют весь пользовательский трафик и не выявляют причину ошибок.

Требуются два уже работающих независимых Xray-клиента или других совместимых клиента с HTTP-прокси, привязанных к loopback и настроенных на разные маршруты. SOCKS-порты напрямую здесь не поддерживаются. Оператор задаёт HTTPS-адрес своей контрольной точки, которая отвечает на HEAD статусом 204 и не перенаправляет запросы. Выберите точку, которую контролируете; оператор ресурса видит IP выхода и время запросов. Системные прокси и переменные окружения для маршрутизации проверок не используются.

Скопируйте `examples/probe-config.json` в личный файл вне Git и замените тестовый домен и порты на свои. Имена маршрутов должны быть обезличенными. Запустите из корня:

```sh
python3 -m adaptive.diagnose --config /путь/к/probe-config.json
```

По умолчанию делается три раунда с интервалом 10 секунд, последовательно по каждому маршруту. Поддерживаются `--rounds` от 3 до 10 и `--interval` от 10 до 300 секунд. Тайм-аут каждого запроса — до 5 секунд, поэтому фактический интервал может быть больше. Результат содержит только идентификаторы маршрутов, количество проб, ошибки, медиану и рекомендацию. Работающая рекомендация не гарантирует, что маршрут готов к использованию для всех программ.

Ограничения: компонент не определяет состояние локальной сети отдельно, не учитывает доступность только отдельных сайтов и не доказывает наличие DPI. При общем сбое сети он может рекомендовать резервный маршрут из-за случайной разницы результатов. Автоматическое применение, TUN, kill switch и сохранение последнего рабочего профиля не реализованы. Не выполнять постоянные или частые проверки без оценки приватности, сетевых следов и расхода батареи. Сбои в точке проверки могут трактоваться как сбои обоих маршрутов; фактический адрес точки, подписки и ключи не публикуйте.

Тесты: `python3 -m unittest discover -s tests -v`. В тестовом стенде используется имитация соединения и локальный HTTP-прокси, возвращающий ошибку CONNECT. Реальных HTTPS-проб через Xray и клиентских проверок на Debian/iOS не проведено.
