# Экспериментальный выбор маршрута

Модуль анализирует заранее полученные результаты проверок и выдаёт рекомендацию. Он не измеряет сеть, не подключается к Xray, не меняет маршруты и не защищает трафик. Данные в примере вымышлены. Для работы требуются Python 3 и как минимум два отдельно настроенных и проверенных маршрута; интеграция с клиентом пока отсутствует.

Запуск из корня репозитория:

```sh
python3 adaptive/selector.py examples/measurements.json
python3 -m unittest discover -s tests -v
```

Формат: `current` — имя текущего маршрута, `routes` — объект с именами маршрутов и массивами результатов в порядке от старого к новому. У каждого результата `ok` — boolean; у успешного дополнительно неотрицательная конечная `latency_ms`. Используются последние три результата: маршрут считается здоровым, если есть три измерения, последнее успешно и как минимум два успешны. Задержка — средний по порядку результат среди успешных измерений (при двух — больший). Если текущий маршрут нездоров, предлагается здоровый с минимальной оценкой; если здоров, другой предлагается только при выигрыше не менее 25% и 50 мс. При отсутствии здоровых маршрутов результат `hold`, без рекомендаций прямого выхода. Равенство оценивается по имени маршрута. Входные данные и актуальность измерений предоставляются вызывающей стороной; модуль не проверяет время или происхождение данных.

Пороговые значения — начальная эвристика, не гарантия качества или обхода DPI. Ошибки могут быть вызваны самим ресурсом, DNS, отсутствием интернета или сбоем сервера. Проверки способны раскрыть метаданные оператору тестового ресурса и создать узнаваемый шаблон трафика. Будущая интеграция должна проверять данные из реальной сети, ограничивать частоту и обеспечивать откат, защиту от утечек и отсутствие прямого обхода туннеля. Переключение существующих сессий не обещается.
